# AttendX V1.1.8 — Student Intelligence & Weighted Attendance

V1.1.8 turns the student roster into an operational attendance workspace. It adds individual profiles, subject-level analytics, attendance calendars, target-based standing, weighted Late credit, stronger private-data boundaries, and additional recovery hardening while retaining the live-attendance and security foundation introduced in V1.1.7.

This is an in-place upgrade from V1.1.7. It does not contain deployment databases, student rosters, attendance exports, backups, credentials, local configuration, or institution-specific operational data.

## Highlights

- Redesigned student workspace with glass card and compact table views, natural roll ordering, search, filters, standing indicators, and saved view preference.
- Dedicated student profiles with overall performance, subject breakdowns, monthly attendance calendar, recent attendance timeline, absence streaks, and recovery guidance.
- Individual student review-workbook export using the same server-authoritative attendance calculations as institution reports.
- Optional enrolment number, section, admission date, phone, guardian contact, and administrative notes.
- Private phone, guardian, notes, and card-token data restricted to administrators for both reads and writes, even if CR student-management permissions are delegated.
- Configurable attendance target used for Good, Needs attention, Critical, and No data standing.
- Admin++ Late credit policy supporting full (`1`), half (`0.5`), or zero (`0`) credited attendance.
- Late policy snapshotted into each new session and numeric credit snapshotted into each attendance record so future settings changes cannot rewrite history.
- Weighted overall and subject percentages while retaining separate physical-appearance totals for Present plus Late.
- Two additive, idempotent database migrations for student profiles and numeric attendance credit.
- Safer asynchronous student search, validated history filters, resilient malformed-setting handling, and controlled recovery after restore failures.
- Refined protected-area, progress, form, privacy-notice, and student-management presentation while preserving the established glass interface.

## Database changes

### `006-student-profile`

Adds nullable student fields:

- `enrollment_number` with a unique index when supplied
- `section`
- `phone_number`
- `guardian_phone`
- `notes`
- `admission_date`

The migration is additive and checks existing schema before changing it.

### `007-late-attendance-credit`

- Adds nullable `late_attendance_credit` to attendance sessions.
- Adds non-null `attendance_credit_value` to attendance records.
- Backfills existing records from the prior boolean credit field (`true → 1`, `false → 0`).

Existing session status, student records, and historical attendance are preserved.

## Upgrade from V1.1.7

Create and retain a tested backup before updating:

```bash
npm run backup
git pull origin main
npm install
npm run config-check
npm run doctor
npm run dev
```

After upgrading:

1. Sign in as Admin++ and review **Settings → Attendance policy**.
2. Confirm the attendance target and Late credit choice (`1`, `0.5`, or `0`).
3. Open several student profiles and verify subject totals against a review export.
4. Confirm CR accounts cannot see private phone, guardian, notes, or card-token values.
5. Keep the pre-upgrade backup until the deployment has completed an attendance and export smoke test.

No destructive migration or roster re-import is required.

## Security and privacy

- Student phone, guardian contact, administrative notes, and card tokens are omitted from CR responses.
- The backend rejects non-ADMIN writes to those private fields even if configuration grants CR create/update capabilities.
- Student profile responses use private no-store caching.
- Password hashes, refresh-token hashes, token history, and IP hashes remain redacted from browser database views.
- Access tokens remain short-lived and memory-only; refresh tokens remain hashed at rest and cookie-restricted.
- Admin elevation remains session-bound, memory-only, rate-limited, and five minutes long.
- Malformed history filters are rejected before database queries.
- Restore failures remove staged uploads and preserve the previous live database where recovery is possible.
- Live databases, backups, local YAML, environment files, exports, logs, uploads, and recovery archives remain excluded from Git.

## Compatibility and scope

- Supported runtime remains Node.js 20 or newer.
- SQLite remains the primary local deployment database; PostgreSQL configuration remains supported by the application.
- V1.1.8 remains one institution per isolated deployment.
- This release does not introduce multi-tenant isolation, billing, customer self-provisioning, faculty accounts, or an operator control plane.
- Existing Admin++ assignment and revocation remain CLI-only through `npm run admin-pp`.

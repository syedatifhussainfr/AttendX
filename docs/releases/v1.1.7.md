# AttendX V1.1.7 — Recoverable Attendance & Hardened Operations

V1.1.7 strengthens live attendance reliability, privileged administration, session security, timetable integrity, and operator tooling. It is an in-place upgrade from V1.1.6 and does not include deployment databases, rosters, attendance exports, backups, credentials, or local configuration.

## Highlights

- Crash-safe attendance write-ahead queue with reconnect and reload recovery.
- Present, Late, and Remove tools with pending-roll review before closure.
- Session closure blocked while locally saved changes remain unsynchronized.
- Race-safe refresh-token rotation for parallel same-browser requests while retaining cross-device reuse protection.
- Password-confirmed ADMIN access to Users and Admin++ access to Database, Backups, permission policy, and destructive operations.
- Admin++ role changes between ordinary ADMIN and CR accounts; Admin++ promotion and revocation remain CLI-only.
- Settings-based CR/ADMIN permission editor with backend-enforced Admin++ capabilities and privilege ceilings.
- Strict timetable time, active-subject, and overlap validation.
- Configurable Late Mode and CR live-correction policy with per-session inheritance.
- Stronger SQLite backup validation, audited backup deletion, and improved restore controls.
- Structured audit display, text export, guarded history deletion, and legacy timestamp normalization.
- Accessible modal focus trapping, restoration, keyboard containment, and background scroll locking.
- Organized configuration recovery archives and new timetable, backup inventory, and release-doctor commands.

## Upgrade from V1.1.6

```bash
git pull origin main
npm install
npm run config-check
npm run backup
npm run doctor
npm run dev
```

Keep a tested off-machine backup before upgrading. `config-check` preserves valid local choices and organizes historical recovery files under `config/archive/`. Review the permission matrix in Settings after the application restarts.

## Security and privacy

- Access tokens remain short-lived and memory-only.
- Refresh tokens remain hashed at rest and restricted to `HttpOnly`, `SameSite=Strict` cookies.
- Elevation tokens are session-bound, memory-only, and expire after five minutes.
- Admin++ capabilities and privilege ceilings are enforced by the backend regardless of YAML or browser input.
- Database views redact password hashes, refresh-token material, token history, and IP hashes.
- Live databases, backups, local `config.yml`, environment files, exports, uploads, logs, and recovery archives are excluded from Git.
- No real student, attendance, administrator, credential, device-session, or local filesystem data is attached to this release.
